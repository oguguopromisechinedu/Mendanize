# Mendanize Engineering Specification (MES-019)
## Ask Mendanize AI Platform

**Version:** 2.0 — supersedes the earlier draft; resolves a public-vs-gated conflict with the Article/Guide/Tool page specs
**Dependencies:** MES-002 (Shared Services — AI Service), MES-018 (Recommendations), MSEM Appendix A

---

## THE FIX

The earlier version of this spec scoped Ask Mendanize AI as Dashboard-only, auth-gated. But the public Article, Learning Guide, and AI Tool page specs all embed contextual "Ask about this" entry points directly on public pages. Those aren't in conflict once split into two tiers of the same feature:

### Tier 1 — Public Contextual Widget
- Lives embedded on public Article/Guide/Tool pages (per those specs).
- Lightweight: a scoped question box tied to the current page's content, single-turn, no persistent history.
- No login required — anonymous, ephemeral session only.
- Uses the AI Service (MES-002) with the current page's content as context.

### Tier 2 — Full Ask Mendanize AI Dashboard Experience
- Auth-gated, at `/dashboard/ask` (or persistent panel).
- Full conversation history, prompt templates, suggested questions, multi-turn context — everything the original spec described.
- An anonymous user engaging with Tier 1 who wants to continue the conversation is prompted to sign in, which hands off into Tier 2 with that conversation's context carried over.

This mirrors the Teaching Frontend → Dashboard handoff pattern already established for the rest of the platform — public taste of the feature, sign-in to go deeper.

---

## BUILD (both tiers)

- Public contextual widget component (Tier 1), embeddable in Article/Guide/Tool pages.
- Full chat interface, conversation history, suggested questions, prompt templates (Tier 2) — as previously specified.
- Related Learning Resources panel — now calls the Recommendations Service (MES-017) instead of ad hoc logic.
- AI Configuration — this module does **not** define its own AI settings screen. It links to the Settings Service's (MES-002) canonical AI configuration, owned by the Platform Settings module. This resolves the earlier duplicate-AI-settings conflict.

---

## DATA MODEL

`Conversation, Message, MessageRole, PromptTemplate, AIFeedback` — Tier 2 only. Tier 1 widget interactions are ephemeral and not persisted unless the user signs in and continues into Tier 2.

---

## SCOPE OF THIS PHASE

Build: both tiers' interfaces, the handoff mechanic between them, conversation architecture and database models for Tier 2.
Do NOT build yet: live AI provider wiring (the AI Service's actual model call — sequenced once the service layer from MES-002 is real), real usage-limit enforcement (ties to Billing, MES-020), real moderation logic.
