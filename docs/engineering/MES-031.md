# Mendanize Engineering Specification (MES-031)
## AI Knowledge Generation Pipeline

**Version:** 1.0 — new module, does not exist elsewhere in the sequence. Connects MES-019 (Ask Mendanize AI, public-facing) to MES-011 (Admin AI Studio, admin-facing) via an automated knowledge-gap trigger. Confirmed via audit against MES-011, MES-018, MES-019 that no equivalent pipeline exists.
**Dependencies:** MES-002 (Shared Services — AI Service, Content Service), MES-006/MES-030 (Dual Authentication — this pipeline crosses the `PublicUser`/`Admin` boundary and must do so only in the direction described below), MES-011 (Admin AI Studio — this pipeline's generation step reuses it, does not duplicate it), MES-014 (Media Library), MES-015 (SEO Service), MES-018 (Recommendations/Content search), MES-019 (Ask Mendanize AI), MES-020 (AI Configuration), MSEM Appendix A

Follows MSEM Appendix A. No exceptions.

---

## OBJECTIVE

When a visitor uses Ask Mendanize AI (MES-019, Tier 1 or Tier 2), the AI system prioritizes Mendanize's own knowledge base before generating new educational content. Every answered question should, over time, strengthen the platform's own content rather than only ever producing ephemeral chat answers.

---

## THE CROSS-BOUNDARY RULE (per MES-030)

This is the one place in the platform where a `PublicUser` action causes `Admin`-side data to be created. That is allowed, but only as a **one-way, backend-only trigger**:

- The visitor's request never directly writes to any `Admin`-owned table. It calls the AI Gateway (a service, not a route), which — if it decides generation is needed — enqueues a job.
- The visitor's session gains no visibility into the resulting draft, its status, or any part of the AI Knowledge Center. They simply get their conversational answer (per MES-019) while the pipeline runs independently.
- Nothing here creates a new session type or grants a `PublicUser` any dashboard access. The isolation MES-030 establishes is unchanged; this is a backend event, not a permissions exception.

---

## REQUEST FLOW

1. **Visitor asks a question** via Ask Mendanize AI (MES-019).
2. **AI Gateway searches existing knowledge** — Articles, Guides, AI Tools, Categories, Topics, and previously-published AI Knowledge Items — via the Content Service (MES-002), not a new search implementation.
3. **If high-quality existing content covers it:** return it, with a conversational explanation grounded only in that trusted content. No generation triggered. This is the common path and should be the vast majority of requests once the knowledge base has depth.
4. **If no suitable content exists:** the Gateway enqueues a job for the Dashboard AI Orchestrator. The visitor still gets a best-effort conversational answer per MES-019's existing behavior — this pipeline runs asynchronously, it does not block or delay their response.
5. **Orchestrator generates a structured draft** via the AI Service (MES-002, respecting MES-020's configured provider): Title, Summary, Introduction, Main Sections, Examples, Best Practices, FAQ, Conclusion, SEO Metadata (via SEO Service, MES-015), Suggested Category/Topic, Related Guides/Tools.
6. **Orchestrator generates supporting images** via the AI Service's image provider (MES-002/MES-011) — Featured Image, optional section illustrations — stored in the Media Library (MES-014), tagged as AI-generated.
7. **Draft saved as an AI Knowledge Item**, status `AI Draft`. Never auto-publishes.
8. **Admins notified** (via the Notification Service, MES-024) that a draft is ready for review. Admin actions: Edit, Expand, Approve, Reject, Publish — using the same Article Editor (MES-008) a human-authored article would use; an AI Draft is not a separate content type, it's an Article (or Guide, depending on scope) that started life as `AI Draft` status.
9. **Once published**, it's permanent Mendanize content — indistinguishable from human-authored content to the Content Service, Search (MES-017), and future Ask Mendanize AI requests, which will now find it in Step 2.

---

## ORCHESTRATION RULES

Prefer existing content. Avoid duplicate pages — before generating, the Gateway checks for near-duplicate topics already in the Draft queue or published, and surfaces a merge suggestion instead of creating a redundant draft. Generate only when necessary. Maintain consistent Mendanize voice (per MES-011's existing style guidance). Follow SEO standards (MES-015). Produce genuine educational content, not a chat transcript reformatted as an article.

---

## ADMIN DASHBOARD — AI KNOWLEDGE CENTER

New section under MES-007's AI Platform domain (Admin-gated, per MES-030): AI Draft Queue, AI Review, AI Publishing, AI Content History, AI Generation Logs (via the Logging Service, MES-002/MES-007), Duplicate Detection, Content Merge Suggestions.

---

## DATABASE

Models: `AIKnowledgeItem` (extends/relates to `Article` — status includes `AI Draft` in addition to MES-008's existing states), `AIGenerationJob` (the queued/async unit of work — references the triggering question but never the `PublicUser.id` directly beyond an anonymized log entry, per Appendix A's privacy-conscious analytics posture), `DuplicateCandidate`.

---

## CONTENT OWNERSHIP

Every published AI-generated item is official Mendanize content — no visible distinction to readers. The public interface never exposes AI orchestration, provider details, or the generation pipeline itself.

---

## WHAT NOT TO BUILD

Auto-publishing without human review (never allowed, ever), real-time generation blocking the visitor's chat response, a separate public-facing "AI drafts" surface.

---

## ACCEPTANCE CRITERIA

✓ Existing knowledge searched first via the Content Service. ✓ Generation triggered only on a genuine gap, asynchronously, never blocking the visitor. ✓ Drafts land in the AI Knowledge Center as `AI Draft`, never auto-published. ✓ Generated images stored in Media Library. ✓ Admin review/approve/publish flow reuses the existing Article Editor. ✓ Published items are searchable/reusable by future Ask Mendanize AI requests. ✓ No `PublicUser` session gains any visibility into the Admin-side pipeline. Zero build/TS/lint errors.

---

## STOP

Summarize the pipeline. Explicitly confirm the one-way boundary crossing holds — no `PublicUser` session can read, list, or be granted access to any AI Draft or the AI Knowledge Center. Wait for the next specification.
