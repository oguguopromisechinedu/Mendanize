# Mendanize Engineering Specification (MES-039)

## Professional Growth & Earnings Ecosystem

**Version:** 1.0 — drafted at full scope, marketplaces included, by explicit choice after the scope and legal/financial weight were flagged. This is the largest addition to the sequence so far — not because of page count, but because two of its six hubs move real money between third parties, which is a different category of system than anything else built to date. **Status:** Approved for drafting **Dependencies:** MES-002 (Shared Services), MES-006/MES-030 (Dual Authentication), MES-007 (Admin Dashboard — new Marketplace Moderation domain), MES-009 (Categories/Topics — skill taxonomy reuse), MES-010 (Learning Guides — not "Courses"), MES-018 (Recommendations — reused, not reinvented), MES-019 (Ask Mendanize AI — extended, not replaced), MES-021 (Billing — subscriptions stay separate from marketplace payments), MES-036 (Community Platform — reused and extended, not duplicated), MSEM Appendix A

Follows MSEM Appendix A. No exceptions.

## CORRECTIONS AND CONSOLIDATIONS (read before building)

This document reintroduces several things that already exist under different names, and a few that don't exist at all. Both matter:

**Already built — reused, not reinvented:**

- "Courses" → Learning Guides (MES-010).
- "AI Tutor" → Ask Mendanize AI (MES-019), extended with new prompt contexts, not a second AI system.
- "Learning Recommendations" → the Recommendations Service (MES-018).
- Community Hub's Study Groups, Discussions, Team Projects, Project Showcase → **MES-036, verbatim.** This spec adds only what MES-036 doesn't already have: Mentorship, Leaderboards, Community Challenges, Hackathons.
- "AI Gateway" → the AI Service (MES-002), already multi-provider.

**Don't exist yet — genuinely new, scoped honestly below:** Certificates, Assessments, Career Hub (all of it), Work Marketplace (all of it), AI Tools Marketplace (all of it), a learner-facing Prompt Library and Notes.

**Deliberately NOT built in this phase, flagged for a reason:** a real code-execution engine for "Coding Workspace." Running arbitrary user-submitted code is a security-critical system in its own right — sandboxing, resource limits, container escape prevention — on the same order of seriousness as the marketplace payment rails below. It gets its own future spec once actually scoped, not a bullet point here. This phase builds Prompt Library and Notes only under "Building Hub."

## THE TWO THINGS THAT ARE GENUINELY DIFFERENT HERE

**1. Real money moving between third parties.** MES-021's billing is subscriptions only — money flows one way, learner to Mendanize. Work Marketplace (clients pay learners for jobs) and AI Tools Marketplace (buyers pay creators for products) both need **Stripe Connect**, not Stripe Checkout — a fundamentally different payment architecture: escrow/milestone holds, creator payout accounts, marketplace fee splits. This is deliberately kept as its own payment rail, separate from MES-021, the same way MES-036 kept Community data out of the Content Service.

**2. Real legal and business decisions this spec doesn't resolve on its own.** Using Stripe Connect as the payment facilitator is the standard reason small marketplaces don't need to become a licensed money transmitter themselves — Stripe holds that license, not Mendanize. But Terms of Service covering marketplace conduct, IP ownership of sold AI tools, dispute resolution, and tax-reporting thresholds (1099-K/1099-NEC, which Stripe Connect + Stripe Tax can generate but doesn't decide *when* they're legally required for you) are real legal and business questions, not engineering ones. This spec assumes those get resolved with an actual lawyer/accountant before launch — it is not a substitute for that, and nothing here should be read as legal advice.

## ARCHITECTURAL PLACEMENT

No new session type. Per MES-030, there are still only two: `PublicUser` and `Admin`. Two new **flags** on `PublicUser` (same pattern as MES-036's Community Moderator flag):

- **Client flag** — lets a `PublicUser` post jobs in Work Marketplace. Anyone can be both a learner and a client; it's a capability, not a separate account type.
- **Creator flag** — lets a `PublicUser` list products in AI Tools Marketplace.

Both live at `/account/*` (client dashboard at `/account/hiring`, creator dashboard at `/account/marketplace`) — never under `/dashboard/*`, which stays `Admin`-only per MES-030. Marketplace and job-posting **moderation** is a new domain added to MES-007.

## HUB 1 — LEARNING HUB (mostly existing, two genuine additions)

Learning Guides (MES-010), Ask Mendanize AI (MES-019) — both reused as-is.

**New: Assessments.** A simple multiple-choice quiz attached to a Guide, pass/fail threshold, `AssessmentAttempt` recorded per `PublicUser`. This is the minimum viable version — no proctoring, no anti-cheating system.

**New: Certificates.** Issued automatically when a `PublicUser` completes a Guide's lessons (per MES-010's existing structure) and passes its Assessment. A `Certificate` is a real, verifiable record (public verification URL), not a badge image — this is what "Certificates Earned" and "Verified Skills" downstream actually point to.

## HUB 2 — BUILDING HUB (scoped down from the original draft)

**Prompt Library** — a `PublicUser`'s own saved/organized prompts. Genuinely new, low complexity. **Notes** — simple per-`PublicUser` notes, optionally attached to a Guide or Lesson. Genuinely new, low complexity. **Projects** → reuses MES-036's `ShowcaseProject` directly, not a new model. **Coding Workspace** — interface and data model only (a project can reference a workspace); the actual execution engine is explicitly out of scope here, see above.

## HUB 3 — COMMUNITY HUB (MES-036 + four net-new pieces)

Study Groups, Discussions, Team Projects, Project Showcase — **MES-036, unchanged.** **New: Mentorship** — a `MentorshipRelationship` (mentor `PublicUser`, mentee `PublicUser`, status). No matching algorithm in this phase — manual request/accept only. **New: Leaderboards** — a computed/cached ranking over MES-036's reputation tally plus this spec's new reputation inputs (below). Recalculated periodically, never a live query over the whole user base. **New: Community Challenges / Hackathons** — a `Challenge` (time-boxed, category, prompt) with `ChallengeSubmission`s judged by Admins or Community Moderators (MES-036's existing flag, not a new one).

## HUB 4 — CAREER HUB (genuinely new)

**Resume Builder / Portfolio Builder** — a `CareerProfile` extending MES-036's `CommunityProfile` (not duplicating it) with resume fields; portfolio pulls from existing `ShowcaseProject`s rather than a separate portfolio data model. **Interview Coach** — a mock-interview mode of Ask Mendanize AI (MES-019) with an interview-specific prompt context. Text-based in this phase — no video/audio recording. **Career Readiness Score / Skill Gap Analysis** — a computed score from real inputs that already exist by this point in the spec (Certificates, Assessments passed, Guides completed, verified skills) — rules-based, like MES-018's Recommendations were in their first phase, not an ML model. **Skill taxonomy** reuses MES-009's Categories/Topics rather than inventing a parallel skills list.

## HUB 5 — WORK MARKETPLACE (new payment rail — Stripe Connect)

Clients (flagged `PublicUser`s) post `JobPosting`s. Learners apply (`JobApplication`), a `Contract` is formed with `Milestone`s, payment held and released per milestone via Stripe Connect, `ClientReview` recorded on completion. **Admin oversight:** every `JobPosting` and `Contract` is visible in the new Marketplace Moderation domain (MES-007) — reports of non-payment, scope disputes, or policy violations land there.

## HUB 6 — AI TOOLS MARKETPLACE (new payment rail — Stripe Connect)

Creators (flagged `PublicUser`s) publish `MarketplaceListing`s (AI Apps, Agents, Prompt Packs, Templates, Automations) with one-time purchase or subscription pricing. Buyers purchase/subscribe via Stripe Connect; `CreatorPayoutAccount` tracks payout status; `MarketplaceReview` and `CreatorFollower` support discovery. **Admin oversight — this one matters more than it looks:** every listing goes through a review queue **before** it's publicly purchasable, the same way an app store reviews submissions — not just a post-hoc reporting system. A marketplace selling "AI Agents" and "Automation Systems" without any pre-publication check is a real liability and quality problem, not a hypothetical one.

## REPUTATION SYSTEM (extended, not replaced)

`ReputationScore` is a computed aggregate reading from: MES-036's existing community tally, plus Certificates earned, Jobs completed, Client reviews, Marketplace sales, Followers, Mentorship activity. Recalculated on a schedule, never hand-edited, never a single flat stored number treated as ground truth.

## NOTIFICATIONS

All new notification types (job invitations, proposal accepted, marketplace sale, certificate earned, challenge results, mentions, follower activity) route through the existing Notification Service (MES-002/MES-024) — no new delivery pipeline.

## AI ASSISTANT EXTENSION

Every new capability listed in the original draft (resume review, proposal generation, interview prep, business coaching) is a new prompt context inside the **existing** Ask Mendanize AI (MES-019) — this spec adds prompt templates and context sources, not a second assistant.

## ADMIN DASHBOARD ADDITION

A **Marketplace** domain added to MES-007: Job Posting Review, Contract Disputes, AI Tool Listing Review Queue, Payout Issue Reports — alongside the existing Community domain (MES-036), not replacing it.

## DATABASE (grouped by hub)

**Learning:** `Assessment, AssessmentQuestion, AssessmentAttempt, Certificate` **Building:** `PromptLibraryEntry, LearnerNote` (both `publicUserId`-scoped) **Community additions:** `MentorshipRelationship, Leaderboard (cached), Challenge, ChallengeSubmission` **Career:** `CareerProfile, ResumeVersion, InterviewSession, CareerReadinessScore, SkillGapResult` **Work Marketplace:** `ClientFlag (publicUserId, grantedOrSelfServe, per Admin policy), JobPosting, JobApplication, Contract, Milestone, ContractPayment (Stripe Connect refs), ClientReview` **AI Tools Marketplace:** `CreatorFlag (publicUserId), MarketplaceListing, MarketplacePurchase, MarketplaceSubscriptionInstance, CreatorPayoutAccount (Stripe Connect refs), MarketplaceReview, CreatorFollower` **Cross-cutting:** `ReputationScore (computed/cached, sourced from the above plus MES-036)`

Every learner-side foreign key is `publicUserId` (MES-006/MES-030). Every admin moderation action (listing approval/rejection, dispute resolution) is Audit-logged (MES-002), same as everywhere else.

## WHAT NOT TO BUILD IN THIS PHASE

The Coding Workspace execution engine (future, dedicated security spec). Real-time chat/negotiation for job proposals (MES-036 already deferred messaging platform-wide). Video interviews. ML-based skill-gap analysis or job matching (rules-based first, same pattern as Recommendations). Automated dispute resolution (human-reviewed only, via the new Admin Marketplace domain). Affiliate/referral payouts. International tax handling beyond what Stripe Tax provides out of the box.
