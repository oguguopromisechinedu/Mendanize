# Mendanize Engineering Specification (MES-049)

## Recommendations ML Upgrade

**Version:** 1.0 — upgrades MES-018 from rules-based scoring toward real ML, without deleting the rules fallback.  
**Status:** Complete  
**Dependencies:** MES-002, MES-017, MES-018 (canonical Recommendations Service — **extend**), MES-022 (signals), MES-023 (events), MES-033 (cache), MSEM Appendix A

Follows MSEM Appendix A. No exceptions.

---

## OBJECTIVE

Improve recommendation quality using offline-trained or managed-ML ranking over existing engagement signals — while keeping MES-018 as the only public API other modules call.

---

## APPROACH

- **Single facade:** Search, Personalization, public pages still call MES-018 only.  
- **Shadow → canary → default:** new model scores in shadow mode first; compare against rules; then percentage rollout.  
- **Features:** views, saves, completions, Ask topics, taxonomy affinity (MES-009) — from MES-022/023, not a new event bus.  
- **Fallback:** if model/store unavailable, rules-based MES-018 path remains authoritative.  
- **Privacy:** no training export of raw PII; aggregate/pseudonymous IDs only (MES-035).

Admin: simple quality dashboard (click-through proxy metrics) under existing Analytics/Recommendations settings — not a sixth analytics platform.

---

## WHAT NOT TO BUILD

A second Recommendations Service. Real-time deep learning in the request path with no timeout budget. Cross-product “Ads Auction.” Rebuilding Knowledge Graph as a graph database (MES-018's lightweight relationships stay).

---

## ACCEPTANCE CRITERIA

✓ All consumers still import MES-018 only. ✓ Fallback to rules works under failure. ✓ Rollout can be disabled instantly via settings. ✓ No `PublicUser` PII leaves the platform for training without MES-035-compatible handling. Zero build/TS/lint errors.

---

## STOP

Document model host (in-house vs vendor) and rollback switch. Wait for next spec.
