# Mendanize Engineering Specification (MES-047)

## Enterprise Organization Licensing

**Version:** 1.0 — rightsized from MES-040 deferred items (enterprise license SKUs, recruitment plan billing). Extends Organizations; does not create a third session type.  
**Status:** Complete  
**Dependencies:** MES-006/MES-030, MES-007, MES-021 (Checkout + entitlements — **reuse**, do not fork billing), MES-040 (Organization / members), MSEM Appendix A

Follows MSEM Appendix A. No exceptions.

---

## OBJECTIVE

Sell seat-based organization plans so a verified Company can license Ask volume, marketplace posting limits, or learning seats for members — using MES-021's Stripe Checkout, not a new billing stack.

---

## MODEL

- `OrganizationPlan` catalog (Admin-managed): name, seat limit, entitlement flags, Stripe Price ids.  
- `OrganizationSubscription` linked to `Organization` + MES-021-style Stripe customer/subscription ids owned by the org Owner's billing identity (document the exact customer association).  
- Seat assignment: map `OrganizationMember` → consumed seat. Owner/Admin of org manage seats at `/account/company/billing`.  
- Entitlements checked server-side the same way MES-021 gates individuals — org membership grants shared caps where configured.

Verification (MES-040) may be required before purchasing certain plans.

---

## ADMIN

Plan CRUD, org subscription visibility, manual seat adjust with audit log. No “login as org.”

---

## WHAT NOT TO BUILD

Full HRIS. Custom SSO/SAML (future MES if an enterprise contract requires it). Government procurement workflows. Separate Employer session. Interview scheduling suites (separate if needed). Recreating MES-039 Stripe Connect for seats.

---

## ACCEPTANCE CRITERIA

✓ Org Owner can buy a seat plan via MES-021 Checkout patterns. ✓ Seat limits enforced for members. ✓ Cancel/change updates entitlements. ✓ Dual-auth: org billing never opens `/dashboard/*`. Zero build/TS/lint errors.

---

## STOP

Confirm single Stripe Checkout rail with MES-021. Wait for next spec.
