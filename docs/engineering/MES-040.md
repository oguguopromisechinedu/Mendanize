# Mendanize Engineering Specification (MES-040)

## Company & Organization Accounts + Hybrid Marketplace Labeling

**Version:** 1.0  
**Status:** Complete (MVP)  
**Dependencies:** MES-002, MES-006/MES-030 (Dual Authentication), MES-007 (Admin Marketplace domain), MES-021 (Billing stays separate), MES-039 (Work + AI Tools marketplaces + Stripe Connect)

Follows MSEM Appendix A. No exceptions.

---

## CORRECTIONS

A pasted “Hybrid AI Tools Marketplace & Hybrid Work Marketplace” draft was filed as MES-040 and mislabeled MES-031. That draft is **not** authoritative.

- Real **MES-031** is the AI Knowledge Generation Pipeline (Complete).
- Real **MES-039** already owns Work Marketplace, AI Tools Marketplace, Client/Creator flags, and Stripe Connect.
- MES-040 **extends** MES-039. It does not rebuild marketplaces or introduce a third session type.

---

## OBJECTIVE

Enable businesses and organizations to participate in the Mendanize ecosystem as first-class actors:

1. Register and manage a **Company / Organization** profile under `/account/*`.
2. Hire through the existing Work Marketplace with optional **org-linked jobs**.
3. Label AI Tools Marketplace listings as **Official**, **Third-party**, or **Built on Mendanize**.
4. Give Admins an **organization verification** queue alongside existing job/listing review.

---

## ARCHITECTURAL PLACEMENT

Still only two sessions: `PublicUser` and `Admin` (MES-030).

- Organization ownership/membership is data on `PublicUser`, not a new auth domain.
- Employer surfaces live at `/account/company` (and reuse `/account/hiring`).
- Organization capability never grants `/dashboard/*`.
- Creating an organization ensures `ClientFlag` for the owner so they can post jobs (same pattern as MES-039 self-serve client enablement).
- Stripe Connect remains the marketplace payment rail from MES-039; MES-021 Checkout is untouched.

---

## DATA MODEL (MVP)

- `Organization` — profile + verification status
- `OrganizationMember` — roles: `OWNER` | `ADMIN` | `MEMBER`
- `JobPosting.organizationId` — optional FK (personal client jobs remain valid)
- `MarketplaceListing.source` — `OFFICIAL` | `THIRD_PARTY` | `BUILT_ON_MENDANIZE` (default `BUILT_ON_MENDANIZE`)

Organization types (MVP): `COMPANY` | `STARTUP` | `EDUCATION` | `NONPROFIT` | `OTHER`

Verification: `UNVERIFIED` | `PENDING` | `VERIFIED` | `REJECTED`

---

## PUBLIC / LEARNER SURFACES

| Route | Purpose |
|-------|---------|
| `/account/company` | Create/manage company profile, members, verification |
| `/account/hiring` | Post/manage jobs; optional org linkage |
| Tools marketplace cards | Show hybrid source badge |

---

## ADMIN SURFACES

Extend `/dashboard/marketplace`:

- Organization verification queue (approve / reject + note)
- Existing job and listing review unchanged
- Admins may set listing `source` to `OFFICIAL`

---

## DEFERRED (not this MES)

Enterprise license SKUs, demo-request workflows, interview scheduling, full HR role matrix (beyond Owner/Admin/Member), government orgs, recruitment plan billing, full third-party tool CMS field matrix, separate Employer session.

---

## ACCEPTANCE CRITERIA

1. A `PublicUser` can create an Organization and become `OWNER`.
2. Owner gets active `ClientFlag` without Admin session access.
3. Org can be submitted for verification; Admin can approve/reject.
4. Jobs can optionally link to an Organization; personal jobs still work.
5. Marketplace listings expose a hybrid source badge.
6. Zero path from company membership to `/dashboard/*`.
7. No new Stripe Checkout usage for marketplace money movement.
