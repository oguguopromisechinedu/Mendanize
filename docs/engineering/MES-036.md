# Mendanize Engineering Specification (MES-036)

## Community Platform (Phase 1)

**Version:** 1.0 — drafted at full scope per explicit request, reopening an item Cursor's own v1.0 Production Readiness Report had placed on the deferred-to-post-v1.0 list. That deferral was a real, evidence-based call (made after MES-001–028 actually shipped) — this spec proceeds anyway because it was chosen knowingly, not because the original reasoning was wrong. **Status:** Approved for drafting **Dependencies:** MES-002 (Shared Services — Search, Notification, Media, Audit, AI Services, reused rather than duplicated), MES-004 (Public Website Structure — Community is primarily a Teaching Frontend module), MES-006/MES-030 (Dual Authentication — every write action here requires a `PublicUser` session; moderation requires an `Admin` session; the two never cross except through the same one-way pattern MES-031 established), MES-007 (Admin Dashboard — moderation lives here), MES-010 (Learning Guides — project/profile relationships point here, not to a nonexistent "Course" model), MES-014 (Media Library — screenshots/avatars), MES-016 (Navigation — the new nav item is admin-configurable, not hardcoded), MES-017 (Search), MES-019/MES-031 (Ask Mendanize AI + Knowledge Pipeline — reused inside discussions, not reimplemented), MSEM Appendix A

Follows MSEM Appendix A. No exceptions.

---

## OBJECTIVE

Build a first-class Community feature enabling learners to discuss, form study groups and project teams, and showcase completed work — integrated with learner accounts, entirely separate from the Admin Dashboard except for moderation. This should feel like a learning community, not a social network.

---

## CORRECTIONS TO THE ORIGINAL DRAFT (read before building)

Three things in the original design don't match what Mendanize actually is, and would have caused real problems if built as written:

1. **"Course relationship" and "Courses completed" don't exist.** Mendanize's content model is Learning Guides (MES-010), not Courses. Every reference below is corrected to Learning Guides.
2. **Team role "Admin" collides with the platform's** `Admin` **RBAC role (MES-030).** That token means something very specific and security-critical elsewhere in this system — a session type gated to `/dashboard/`\*. A team-scoped role reusing that word is a real bug waiting to happen (permission checks, UI labels, and Cursor's own code search would all become ambiguous). Team roles below are **Owner / Lead / Member**.
3. **"Certificates earned" and "learning progress" don't exist as real systems.** MES-010 explicitly modeled progress tracking as a placeholder, and it's on the same deferred-to-post-v1.0 list as Community itself. Profile fields referencing these are placeholder-only until those systems are real — Community does not get to quietly assume they exist.

---

## ARCHITECTURAL PLACEMENT

Per MES-001's three-surface model, Community isn't a fourth surface — it's a module that spans two of the three, the same way Ask Mendanize AI does:

- **Public browsing** (discussions, groups, projects — read-only) lives on the **Teaching Frontend**, no login required, at `/community`.
- **Posting, replying, joining, creating** requires an authenticated `PublicUser` session (MES-006/MES-030) — the same Learner Account Area auth as everything else at `/account/`_, applied here at `/community/_` action routes.
- **Moderation** (remove content, manage reports, manage categories, feature projects) requires an `Admin` session, lives under `/dashboard/community`, and is a new domain added to MES-007's dashboard architecture.

No new session type, no new surface. This is the same pattern already established — reused, not reinvented.

---

## WHERE COMMUNITY DATA LIVES (not the Content Service)

Community data (Discussions, Groups, Teams, Projects) is **not** part of the Content Service (MES-002) — that service is scoped to editorial content (Articles, Guides, Tools, Categories, Topics, Authors). Community content is user-generated. This module owns its own models directly, the same way Billing (MES-021) owns `Subscription` without routing it through the Content Service. It **does** reuse the cross-cutting shared services: Search (MES-017), Notification (MES-002/MES-024), Media (MES-014), Audit (MES-002), and AI (MES-019/MES-031).

---

## NAVIGATION

A new primary nav item, "Community," routed to `/community` — added through the Navigation Manager (MES-016), not hardcoded, per the Design Customization Principle (MES-001).

## COMMUNITY HOME

Welcome banner, search (via Search Service), trending/latest discussions, recommended groups, active teams, featured learner projects. Upcoming learning events is deferred — no events system exists yet; omit or placeholder it, don't build one now.

## DISCUSSION CATEGORIES

Categories (Artificial Intelligence, Prompt Engineering, Programming, Web Development, Mobile Development, Machine Learning, Data Science, UI/UX, Career Advice, Certifications, General Discussion, Community Help) each support discussions, replies, likes, views, tags, search, sorting, pagination — standard CRUD over the module's own models, no special logic per category.

## STUDY GROUPS

Create/join public groups, request access to private groups, leave, view members, pin resources, share notes. **"View learning progress" is a placeholder** until MES-010's real progress tracking exists — do not fake this with static numbers. Group owners: edit, remove members, assign moderators (group-scoped, not platform `Admin`), archive.

## TEAM PROJECTS

Teams have: name, description, category, skills required, visibility, members, roles, progress status (a simple manual status field — Not Started/In Progress/Complete — not tied to any real progress-tracking system). **Roles: Owner / Lead / Member** (renamed from the original draft's Owner/Admin/Member to avoid colliding with the platform `Admin` role). Team page: Overview, Members, Tasks (placeholder), Resources, Discussion, Files (placeholder), Activity.

## PROJECT SHOWCASE

Title, Description, Screenshots (via Media Library, MES-014 — not a separate upload path), Technologies, **Learning Guide relationship** (optional link to a MES-010 Guide, corrected from "Course relationship"), Team or Individual, Demo link, Repository link. Community members can like, comment, bookmark.

## ASK MENDANIZE AI INTEGRATION (reused, not reimplemented)

Inside a discussion, "Ask Mendanize AI" reuses the existing Tier 2 conversational flow (MES-019) — the poster is already an authenticated `PublicUser` to be posting at all, so this is Tier 2 behavior, not Tier 1. It searches existing knowledge first (Search Service, same as MES-031's Gateway); if found, answers conversationally; if genuinely absent, generates a fresh answer and **that generation optionally also feeds MES-031's AI Draft queue** — same one-way boundary rule applies: the `PublicUser` who asked never sees or gains access to that queue. The user can insert the AI's conversational answer into their own reply — that's a UI action on content they already have, not a new backend capability.

## SEARCH

Community search (discussions, groups, teams, projects, tags) is implemented **through the existing Search Service (MES-002/MES-017)**, extended to index these new content types — not a separate search implementation. Filters: Category, Popularity, Date, Most Active.

## NOTIFICATIONS

Reply, mention, team join, group join, project feedback — all dispatched through the existing Notification Service (MES-002/MES-024), which already owns in-app and email notification delivery. No new notification pipeline.

## COMMUNITY PROFILE

A `CommunityProfile`, one-to-one with `PublicUser` — separate from MES-022's learning/personalization models, since bio/skills/reputation are community-specific, not general account data. Fields: Avatar (Media Library), Bio, Skills, Study Groups, Teams, Showcase Projects, Community Reputation (a simple point count from likes/helpful replies — not a personality or behavioral profile, just an activity tally). **"Certificates earned" and "Learning Guides completed" are placeholder fields** — real data only once a certificate system and MES-010's real progress tracking exist; don't display fabricated numbers in the meantime.

## MODERATION

Report discussion/comment/project, hide inappropriate content, community guidelines page. Two distinct levels of moderation authority:

- **Community Moderators** — trusted `PublicUser`s granted a community-scoped moderator flag by an `Admin` (from the new Admin Dashboard domain below). They can hide/remove content and manage reports **within** `/community` **only** — this flag never grants any `/dashboard/`\* access. This is a genuinely new, narrow permission, distinct from MES-030's `Admin` RBAC roles.
- **Platform** `Admin` — full moderation, pin discussions, manage categories, manage reports, feature projects, grant/revoke the Community Moderator flag — via `/dashboard/community`.

## PERMISSIONS SUMMARY

- **Public visitors:** browse public discussions and projects — no auth.
- `PublicUser`**:** create discussions, reply, join groups, create teams, publish showcase projects, request Community Moderator status.
- **Community Moderator** (a flagged `PublicUser`): the above, plus hide/remove content and manage reports within `/community`.
- `Admin`**:** full moderation authority via `/dashboard/community`, per MES-030's existing RBAC.

## ADMIN DASHBOARD ADDITION

A new **Community** domain is added to MES-007's Admin Dashboard Architecture: Moderation Queue, Reported Content, Category Management, Featured Projects, Community Moderator management (grant/revoke the flag above). This is a small addition to MES-007, not a redefinition of it — see the companion patch to that spec.

---

## DATABASE

`CommunityCategory, Discussion (publicUserId, categoryId, tags), DiscussionReply (publicUserId, discussionId), StudyGroup (ownerPublicUserId, visibility), StudyGroupMember (publicUserId, studyGroupId, role), Team (visibility, category, skills), TeamMember (publicUserId, teamId, role: Owner/Lead/Member), ShowcaseProject (publicUserId or teamId, guideId nullable — the corrected Learning Guide relationship), ProjectLike, ProjectComment, ProjectBookmark, CommunityProfile (publicUserId, one-to-one), CommunityModeratorFlag (publicUserId, grantedByAdminId, per MES-030's Audit Service), CommunityReport (contentType, contentId, reporterPublicUserId, reason, status)`.

Every foreign key to a learner is `publicUserId` referencing `PublicUser.id` (MES-006/MES-030) — never a generic `userId`. Every admin-side action (granting a moderator flag, removing content, resolving a report) is logged via the Audit Service (MES-002), same as every other `Admin` action platform-wide.

---

## WHAT NOT TO BUILD

Messaging, live collaboration, badges/gamification beyond the reputation tally, events system, a real certificate system, real learning-progress data (all explicitly deferred, several already on Cursor's own post-v1.0 list). Course-linking (corrected to Learning Guide-linking, but the relationship itself is simple — no automated course/guide recommendation logic here, that's MES-018's job if ever extended to Community content).

---

## ACCEPTANCE CRITERIA

✓ Community Home, Categories, Discussions, Study Groups, Team Projects (with corrected Owner/Lead/Member roles), Project Showcase (with corrected Learning Guide relationship) all exist and are database-backed. ✓ Search and Notifications reuse existing services, no parallel implementations. ✓ Ask Mendanize AI integration reuses MES-019/MES-031, doesn't reinvent them. ✓ Dual-auth boundary holds: no `PublicUser` session reaches `/dashboard/community`, no `Admin` session is required for ordinary Community participation, and the Community Moderator flag is scoped to `/community` only. ✓ Profile fields for progress/certificates are honestly placeholder, not fabricated. Zero build/TS/lint errors.

Summarize completion. Confirm the dual-auth boundary holds under test — specifically that a Community Moderator flag never grants `/dashboard/*` access. Wait for approval before implementing messaging, events, or real progress/certificate integration.
