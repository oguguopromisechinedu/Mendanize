# Mendanize Engineering Specification (MES-046)

## Affiliate & Referral Tracking

**Version:** 1.0 — from the MES-INDEX future roadmap; deliberately separate from MES-039 marketplace payouts.  
**Status:** Complete  
**Dependencies:** MES-002 (Audit), MES-006/MES-030, MES-007, MES-021 (subscriptions — attribution target), MES-023 (optional funnel events), MES-024, MSEM Appendix A

Follows MSEM Appendix A. No exceptions.

---

## OBJECTIVE

Attribute new `PublicUser` signups and qualifying MES-021 subscriptions to a referrer via shareable codes/links — with transparent reward rules — without becoming a multi-level marketing network or a second Stripe Connect marketplace.

---

## MVP

- Each eligible `PublicUser` gets a referral code / vanity path (`/?ref=CODE`).  
- Cookie or first-touch attribution window (configurable, default 30 days).  
- Record `ReferralAttribution` on signup; convert to `ReferralConversion` when a paid subscription starts (MES-021 webhook).  
- Rewards: account credit, extended trial, or manual Admin payout flag — **pick one primary mechanism** and document it; do not invent a parallel money-movement rail.  
- Self-referral and fraud basics: same email/device heuristics, Admin disable code.

Admin dashboard: codes, conversions, abuse flags. All reward grants audit-logged.

---

## WHAT NOT TO BUILD

Multi-level / nested affiliate trees. Cookie stuffing networks. Merging referral payouts into Stripe Connect creator payouts (MES-039). Tax-form automation beyond what finance later requires.

---

## ACCEPTANCE CRITERIA

✓ Referral link attributes a signup. ✓ Paid conversion records correctly from MES-021. ✓ Self-referral blocked. ✓ Admin can disable a code. Zero build/TS/lint errors.

---

## STOP

Confirm rewards do not invent a third payment processor. Wait for next spec.
