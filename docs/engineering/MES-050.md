# Mendanize Engineering Specification (MES-050)

## Progressive Web App & Offline Learning Basics

**Version:** 1.0 — rightsized mobile delivery. The enterprise paste that once proposed native apps / wearables / AR-VR (dropped MES-051) stays dropped; this MES ships a PWA layer on the existing Next.js app.  
**Status:** Complete  
**Dependencies:** MES-003, MES-004, MES-006/MES-030, MES-022, MES-025–027, MES-028, MES-033, MSEM Appendix A

Follows MSEM Appendix A. No exceptions.

---

## OBJECTIVE

Make Mendanize installable on phones and usable for core learning flows with limited connectivity — without maintaining a separate native codebase.

---

## MVP

- Web App Manifest + service worker for shell caching and offline fallback page.  
- Install prompt UX that respects platform norms (not aggressive nagging).  
- Offline-readable: recently viewed Articles/Guide lessons the user already opened (Cache API / IndexedDB — document quota).  
- Auth: existing cookie sessions; no new mobile OAuth stack. Admin dashboard (`/dashboard/*`) may be **excluded** from PWA install targets — learners are the audience.  
- Push notifications: optional phase-1b only if MES-024 gains a web-push provider; not a blocker for installability.

Performance budgets continue to follow Appendix A / MES-028; PWA must not regress LCP on desktop.

---

## WHAT NOT TO BUILD

React Native / Flutter apps. App Store review pipelines. Wearables, AR/VR, foldables as first-class targets. A separate mobile design system that diverges from MES-003.

---

## ACCEPTANCE CRITERIA

✓ Manifest + service worker ship; app is installable on a supported mobile browser. ✓ Offline fallback and at least one cached learning path work. ✓ Desktop public site remains correct. ✓ Dual-auth cookies still isolate Admin vs PublicUser. Zero build/TS/lint errors.

---

## STOP

Summarize cache strategy and known offline limitations. Native apps remain out of sequence until a real product decision reopens them.
