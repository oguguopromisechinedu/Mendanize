# Mendanize Engineering Specification (MES-022)
## User Learning Experience & Personalization

**Version:** 1.1 — updated for the dual-authentication model (MES-006/MES-030): every reference to "user" below means `PublicUser` specifically, never `Admin`.
**Dependencies:** MES-002, MES-006/MES-030 (Dual Authentication), MES-018 (Recommendations), MSEM Appendix A

Follows MSEM Appendix A. No exceptions.

---

## OBJECTIVE
Give every authenticated learner (`PublicUser`) a personalized learning space — dashboard, saved resources, progress, recommendations — turning Mendanize from a content platform into a personalized one. This entire module is scoped to the Public Authentication domain; it has no admin-facing surface.

---

## BUILD
My Learning Dashboard, Continue Learning, Saved Articles/Guides/Tools, Learning History, Recommended For You, My Interests, Account Preferences — all under `/account/*` (e.g. `/account`, `/account/saved`, `/account/history`, `/account/interests`, `/account/preferences`; billing lives at `/account/billing` per MES-021). This is explicitly **not** `/dashboard/*`, which is Admin-only per MES-030. Gated by an authenticated `PublicUser` session — never accessible to an `Admin` session, and vice versa (per MES-030's session isolation).

## MY LEARNING DASHBOARD
Welcome, Continue Learning, Learning Statistics, Recently Viewed, Saved Content, Recommended Content (via Recommendations Service, MES-018), Learning Streak/Weekly Goal placeholders.

## CONTINUE LEARNING
Guide progress cards: last lesson, remaining lessons, estimated completion, resume button. Real progress tracking is a future spec — this phase builds the interface against placeholder progress data.

## SAVED CONTENT
Saved Articles/Guides/Tools — search, filter, sort, remove, open.

## LEARNING HISTORY
Recently read/viewed/opened content, search history placeholder, Ask Mendanize AI history placeholder (real history exists once MES-019's Tier 2 is live, referencing the same `PublicUser`).

## RECOMMENDED FOR YOU
Calls the Recommendations Service (MES-018) with `contextType: 'publicUser'` — does not reimplement recommendation logic.

## MY INTERESTS
Interest selection from the platform's Category/Topic taxonomy (MES-009) — feeds the Recommendations Service.

## ACCOUNT PREFERENCES
Preferred Difficulty, Learning Goals, Daily Reminder placeholder, Preferred Categories/Topics, Theme (reads from Design Customization, MES-003/MES-020). This is the `PublicUser`'s own account settings — distinct from any `Admin` account settings, which live under MES-030's Users & Roles.

## SECURITY
Private learning history and saved resources — per Appendix A Security Baseline, enforced at the data layer against the `PublicUser.id` on the session, not just hidden UI.

## DATABASE
Models: `UserInterest, SavedArticle, SavedGuide, SavedAITool, LearningHistory, LearningGoal, UserPreference` — every one of these foreign-keys to `PublicUser.id` (per MES-006/MES-030), never a generic `User` or `Admin.id`. `LearningProgress` modeled as placeholder — real tracking depends on Guide lesson completion logic, a future spec.

---

## WHAT NOT TO BUILD
Real recommendation algorithms beyond MES-018's rules-based engine, real progress/streak calculations, email reminders, push notifications, gamification/badges.

---

## ACCEPTANCE CRITERIA
✓ Dashboard, Continue Learning, Saved Content, History, Recommendations, Interests, Preferences all exist, all scoped to `PublicUser` exclusively. Zero build/TS/lint errors.

---

## STOP
Summarize the architecture. Confirm every model here foreign-keys to `PublicUser.id`, not a generic user table. Explain integration with Auth, content modules, Recommendations, and Ask Mendanize AI. Wait for MES-023.
