# Mendanize Engineering Specification (MES-007)

## Enterprise Admin Dashboard Architecture

**Version:** 3.4 — supersedes v2.0, v3.0, v3.1, v3.2, and v3.3. This is a full enterprise-grade architecture: Platform Services integration, Command Palette, Right Context Panel, module auto-registration. Reconciled here with MES-002 (six new shared services folded in, not redefined), MES-030 (dashboard is 100% `Admin`-gated; "Subscribers" clarified as `PublicUser` read-only data, not an RBAC role), MES-031/MES-032 (AI Knowledge Center and Observability now correctly referenced), MES-036 (Community moderation domain, narrow `PublicUser`-scoped moderator flag), MES-039 (Marketplace domain — job/listing review, both new `PublicUser` flags follow the same non-`Admin` pattern), and MES-037 (Business Intelligence domain, the one area gated to Super Administrator specifically rather than the broader `Admin` tier). **Status:** Approved — Critical Foundation **Dependencies:** MES-002 (Shared Services & API Architecture — this dashboard communicates *only* through those services), MES-003 (Design System), MES-006/MES-030 (Dual Authentication — every route here requires an `Admin` session), MES-011 (Admin AI Studio — the "AI Platform" domain below is its dashboard entry point, not a redefinition of it), MES-031 (AI Knowledge Generation Pipeline — its AI Knowledge Center is a section of this dashboard's AI Platform domain), MES-032 (Observability — feeds this dashboard's System Status/Status Bar), MSEM Appendix A

Follows MSEM Appendix A. No exceptions.

---

## OBJECTIVE

Build the single operational control center for Mendanize: Content, Learning, AI, Analytics, SEO, Homepage, Navigation, Users, Security, Settings, Automation, Platform Health. Architecture must scale for years and let every future module register without structural redesign. Every route in this module requires an authenticated `Admin` session (per MES-030) — this dashboard has no `PublicUser`-facing surface anywhere.

---

## ENGINEERING PRINCIPLES

Modular, component-based, service-oriented, scalable, accessible, secure, responsive, high-performance, maintainable, future-proof.

---

## ARCHITECTURE — DOMAINS

**Content:** Articles, Learning Guides, AI Tools, Media Library **Content Structure:** Categories, Topics, Tags **Website:** Homepage Builder, Navigation Manager, Pages, Branding, Header, Footer, Announcement Bar **AI Platform:** Ask Mendanize AI (admin-side config only — the feature itself is MES-019), AI Writer / AI Image Generator (both are MES-011's Admin AI Studio, surfaced here), **AI Knowledge Center** (MES-031's AI Draft Queue, Review, Publishing, Content History, Generation Logs, Duplicate Detection — this domain is where that pipeline's admin surface actually lives), AI SEO Assistant, Prompt Library, AI Configuration (single canonical location — MES-020, not redefined here) **SEO & Growth:** SEO Center (MES-015), Analytics (MES-023), Newsletter, **Subscribers** (read-only view of `PublicUser` accounts who are subscribed — see Users Domain note below), Sitemap, Redirect Manager, Robots Configuration **Users:** Administrators, Editors, Authors — `Admin` **roles per MES-030, managed here with full CRUD.** Subscribers — `PublicUser` **accounts, read-only in this domain** (view subscription/engagement status; no ability to log in as them or modify their public account — that stays inside their own session per MES-030's isolation rule). Roles, Permissions — `Admin` RBAC only (MES-030). **Community (MES-036):** Moderation Queue, Reported Content, Category Management, Featured Projects, Community Moderator management — granting/revoking a `PublicUser`'s community-scoped moderator flag, which is distinct from and never grants any `Admin` RBAC role or `/dashboard/`* access beyond this domain. **Marketplace (MES-039):** Job Posting Review, Contract Disputes, AI Tool Listing Review Queue (pre-publication approval — no listing goes live unreviewed), Payout Issue Reports. Client and Creator flags (MES-039) are `PublicUser`-scoped the same way the Community Moderator flag is — visible and manageable here, never an `Admin` RBAC role. **Business Intelligence (MES-037):** Founder Dashboard, Company Valuation, Growth Analytics, Revenue Analytics, Investor Metrics — gated to the **Super Administrator** role specifically, the one domain in this dashboard not visible to the broader `Admin` tier. **System:** Integrations, API Keys, Security, Workflow, Automation, Backup, Maintenance, Settings (MES-020)

## GLOBAL LAYOUT

Top Navigation, Left Sidebar, Main Workspace, Right Context Panel, Bottom Status Bar.

## TOP NAVIGATION

Global Search, Command Palette, Ask Mendanize AI (admin config entry point), Quick Create, Notifications, Theme Toggle, **Admin** Profile Menu (the signed-in `Admin`, never a `PublicUser`), Workspace Switcher placeholder.

## GLOBAL SEARCH

Indexes Articles, Guides, AI Tools, Categories, Topics, Media, Pages, Homepage Sections, **Admin/Editor/Author records** (never `PublicUser` records — searching subscribers is a separate, permission-gated action within the Users domain, not part of the instant global index), Settings. Instant results.

## COMMAND PALETTE

`CTRL+K`. Search anything, open modules, create content, navigate, run AI commands, quick actions.

## LEFT SIDEBAR

Fully modular: expandable groups, collapse mode, favorites, pinned items, **permission-aware navigation** (an Editor sees a different sidebar than a Super Administrator, per MES-030's RBAC — this is not optional chrome, it's enforced the same way route access is), future dynamic registration.

## RIGHT CONTEXT PANEL

Recent Activity, Notifications, AI Suggestions, SEO Tips, Publishing Checklist, Learning Recommendations (admin-facing — e.g. "this guide has no featured image").

## STATUS BAR

System Health (sourced from MES-032's Observability layer — this is where that spec's health status actually surfaces to an admin), Deployment Status, Storage Usage, AI Credits (per-provider, per MES-002's multi-provider AI Service), Notification Count, Background Tasks.

---

## PLATFORM SERVICES

Every dashboard module communicates only through the shared services defined in **MES-002** — Authentication (MES-006/MES-030), Content, Learning, AI, Analytics, SEO, Notification, Search, Media, Homepage, Navigation, Settings, Logging, Audit. This document does not redefine any of them; it consumes them. No duplicated business logic anywhere in this dashboard.

---

## DASHBOARD HOME

Statistics, Quick Actions, Publishing Workflow, Recent Content, Analytics, Activity Feed, System Status, AI Insights — per the widget shells originally scoped in v2.0, now backed by the full Platform Services layer above.

## QUICK ACTIONS

Create Article, Create Guide, Create AI Tool, Upload Media, Generate AI Image, Generate Article, Generate SEO, Edit Homepage, Create Category, Create Topic.

## PUBLISHING WORKFLOW

Idea → Research → Draft → AI Enhancement → SEO → Media → Review → Approval → Publish → Distribution.

## HOMEPAGE BUILDER

Manages Hero, Featured Articles/Guides/Tools, Categories, Topics, Newsletter, Testimonials, Partners, Footer, Announcement Bar — via the Homepage Service (MES-002/MES-013). Every section: Enable/Disable, Drag-and-Drop (keyboard fallback per Appendix A), Draft, Preview, Publish.

---

## STATE MANAGEMENT

Centralized state: Authentication (`Admin` session only), Sidebar, Theme, Filters, Pagination, Notifications, Search, AI Context, Homepage Preview.

## LOADING STATES

Skeleton Loading, Empty State, Error State, **Permission Denied** (this is the RBAC-aware state MES-030 requires — shown when an `Admin` lacks the role/permission for a route, distinct from a generic error), Offline State, No Results.

---

## PERFORMANCE TARGETS

Initial Load < 2s. Navigation < 300ms. Global Search < 500ms. Analytics lazy-loaded. Images optimized. Code splitting, dynamic imports, Server Components where appropriate. These are stricter than Appendix A's general Performance Standard because this is an internal power-user tool where speed is the product — state this explicitly as this module's justified exception/addition to the appendix.

## SECURITY

Every module here supports: Authentication (`Admin` only), Authorization, Permission Checks, **Audit Logging via the Audit Service (MES-002)** — every admin action logged, per MES-030 — Secure API Access, Input Validation, Session Validation (`AdminSession` specifically, never `PublicSession`), Role Restrictions.

## MODULE REGISTRATION

Every future dashboard module auto-registers: Sidebar Navigation, Routes, Permissions, Analytics, Search, Notifications, Audit Logs, Settings. No manual modification of this architecture required to add a module.

---

## FUTURE MODULES (not built now)

AI Academy, Community, Certifications, Marketplace, Events, Podcasts, Video Courses, Membership, Mobile App Management, Localization, Multi-language Content — tracked per MES-013's Future Placeholder Roadmap pattern, each becomes its own spec once designed.

## ACCEPTANCE CRITERIA

✓ Modular architecture, Platform Services layer consumed (not duplicated), sidebar supports unlimited future modules with permission-aware visibility, Global Search and Command Palette exist, Homepage Builder controls the public homepage via the Homepage Service, centralized state management, all loading/permission states exist, accessibility/performance/security targets met, module registration works, `Admin`-only gating verified end to end, Subscribers correctly read-only and scoped to `PublicUser` data. Zero build/TS/lint errors.
