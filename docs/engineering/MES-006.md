# Mendanize Engineering Specification (MES-006)
## Authentication & User Management

**Version:** 2.0 (renumbered from original MES-005)
**Dependencies:** MES-002, MES-003, MSEM Appendix A

Follows MSEM Appendix A — including its Security Baseline, which applies in full here as this is the module that baseline was written against. No exceptions.

---

## OBJECTIVE
Build the complete authentication and user management foundation: secure auth, session management, user profiles, protected routes, role-based access control. Production-ready, scalable, secure.

---

## PRODUCT CONTEXT
Learners sign in to (future): save progress, bookmark content, personalize experience, access premium content.
Administrators sign in to: manage Articles, Categories, Guides, AI Tools, Homepage, Navigation, SEO, Platform Settings, and the AI Studio (content generation).

---

## BUILD

**Canonical session:** Auth.js (NextAuth v5) with Prisma adapter on Supabase-hosted PostgreSQL.
Support: Sign Up, Sign In, Sign Out, Forgot/Reset Password, Email Verification (UI + model fields), Session Persistence (JWT strategy), Protected Routes via `proxy.ts`.

> Earlier drafts said “Supabase Authentication.” Do not introduce a second session provider. Supabase is the database host.

## USER ROLES
Super Admin, Admin, Editor, Learner. Architecture must allow future role expansion — do not implement role-specific dashboards yet.

## AUTH PAGES
`/sign-in`, `/sign-up`, `/forgot-password`, `/reset-password`, `/verify-email` — responsive, accessible, reusable form components (MES-003), loading/error states.

## USER PROFILE FOUNDATION
Full Name, Profile Image, Email, Account Status, Role, Created/Updated dates.

## SESSION MANAGEMENT
Persistent login, secure logout, expiration handling, automatic token refresh, protected route middleware. **This is the single canonical session contract** — no other module invents its own session logic; all reference this one (per Appendix A Security Baseline).

## DATABASE
Models: `User`, `UserProfile`, `UserRole`. Foundational schema only — no profile management features yet.

## FORM VALIDATION
Email, Password, Password Confirmation — clear validation messages, no invalid submissions.

---

## WHAT NOT TO BUILD
Admin Dashboard, User Dashboard, Learning Progress, Bookmarks, Notifications, Premium Subscription logic (MES-020), Profile Editing.

---

## ACCEPTANCE CRITERIA
✓ Auth fully functional, session management correct, protected routes implemented, roles prepared, pages responsive, forms validated, security baseline followed, zero build/TS/lint errors.

---

## STOP
Summarize the auth architecture. Explain how MES-020 (Billing), MES-021 (Personalization), and MES-007 (Admin Dashboard) will integrate with it. Wait for MES-007.
